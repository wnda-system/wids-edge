What we normally use: everything below can be set freely.
For field experiments the training side compares with AWID3. Fixed settings:
  • channel and width must be set; the adapter is checked with iw and both are saved in the .json
  • one continuous .csv.gz per session, each second written once complete — no memory limit, no packet cap
  • wlan.da follows the DS bits like Wireshark (raw schema 3); every other column unchanged
  • LLC/SNAP decoding on (same as the live monitor)
  • attack periods are marked below while capturing and saved as …_ground_truth.csv
Type the interface name, then click "Enable monitor mode" — it runs the down / set-type / up sequence for you. If you don't know the name yet:
  1. Open a terminal on this computer and run iw dev — it lists your WiFi adapters. Look for one that isn't your normal WiFi connection.
  2. Type that name into the box above and click "Enable monitor mode".
Only needed once per adapter per boot — it stays in monitor mode until you change it back or unplug it. Note: this locks the adapter to one WiFi channel, so it will only see traffic on that channel.
Tuned before the capture starts and checked with iw dev … info; the real channel is saved in the capture's .json file. Leave the channel empty to keep whatever the adapter is on.
Pick at least one — whichever limit is hit first stops the capture. You can also stop manually at any time.
Optional — without a time limit it runs until you press Stop.
"Original" only extracts app-layer fields (tcp./dns./http./arp./eapol./etc) when scapy's own dissection already found them. "LLC/SNAP dispatch" adds a manual fallback that reads the LLC/SNAP header directly off unencrypted Data frames scapy didn't already dissect — same wlan.*/radiotap.* fields either way. Run both against the same traffic to compare.
